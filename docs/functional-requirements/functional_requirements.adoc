== Functional Requirements

F1. The system shall allow users to log in via web or mobile application and validate credentials against an LDAP directory.

F2. The system shall support biometric authentication (Face ID, fingerprint) in the mobile application.

F4. The system shall allow management of users, including roles and permissions.

F5. The system shall allow management of asset categories, including defining different categories and configuring booking time periods for each category.

F6. The system shall support CRUD (create, read, update, delete) operations for assets.

F7. The system shall support asset maintenance management, including tracking and updating maintenance status.

F8. The system shall display the location of assets within buildings or office areas.

F9. The system shall allow users to search assets by category, availability, and time period.

F10. The system shall allow users to book assets (laptop, parking spot, book, meeting room, desk).

F11. The system shall support quick booking (for parking spots, desks, books) via mobile application, with minimal required input from the user.

F12. The system shall support recurring bookings for users with appropriate permissions.

F13. The system shall provide booking confirmation after a successful reservation.

F14. The system shall prevent double booking of the same asset within the same time period.

F15. The system shall generate asset usage reports.

F16. The system shall manage booking expiration by automatically canceling or updating expired reservations.

F17. The system shall notify managers when booking approval is required.

F18. The system shall allow managers to approve or reject booking requests via email or mobile push notification.

F19. The system shall support integration with Google Calendar for booking synchronization (optional).

F20. The system shall support email integration for notifications and communication.

F21. The system shall support QR code integration for asset identification and interaction.
